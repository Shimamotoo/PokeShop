# Domain Docs

This is a single-context repository: the product centers on PokeShop, a Pokémon TCG collector platform.

## Before exploring

- Read `docs/discovery/GLOSSARY.md` for domain vocabulary and listing states.
- Read `docs/discovery/PRODUCT_DISCOVERY.md` and `docs/SPEC.md` for product requirements.
- Read relevant decisions under `docs/architecture/adr/`.
- Treat `docs/architecture/OPTIONS.md` as architecture context; approved ADRs take precedence where they differ.

## Use the glossary's vocabulary

Use terms and state names from the glossary in specs, tickets, and implementation. If a needed term is missing or conflicts with another document, record the gap rather than inventing a silent replacement.

## Flag ADR conflicts

If proposed work conflicts with an approved ADR, surface the conflict and its trade-offs before changing the decision.
